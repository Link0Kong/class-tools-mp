# 作业 SKILL（homework）

班级工具站小程序的「作业」业务：查看待交/已完成作业、作业详情、作业概览，标记完成，发布作业，删除作业。

## 一、数据口径（与作业板页面、网页端完全一致）

### 1. 截止时间怎么算
- 作业行有 `date`（截止日期 `YYYY-MM-DD`）与可选的 `time`（`HH:mm`），**截止时刻 = date 当天 time；没有 time 时按当天 00:00**。
- **没有 `date` 的作业视为「无截止日期」**，不参与过期判断，也不显示倒计时。
- 截止提示文案与页面相同：`还剩 N 天` / `还剩 N 小时` / `已过期 N 小时` / `已过期 N 天` / `无截止日期`。
- 列表默认按「截止时间从近到远」排，无截止日期的排在最后；已完成作业按发布时间倒序。

### 2. 三天后自动清除
- **截止日期过后满 3 个完整天（即 now > 截止时刻 + 3×24 小时）的作业会自动清除**：本机从作业板移除，云端行由主包在下一次打开作业板时归档。
- AI 侧只做「不展示、不返回」：`listHomework` / `getHomeworkDetail` / `getHomeworkSummary` 都不再出现这类作业，**不会**在对话里自动归档或删除云端数据。
- 因此用户问「以前的作业」时，只能查到未满三天清除期的作业；查不到时说明可能已自动清除，并可引导到作业板查看。

### 3. 完成状态
- 完成状态的真源是云端 `marks` 表（`kind=hw`，`ref=作业 id`），本机以 `store.hwDone` 镜像；网页端与小程序的勾选状态互通。
- 早期没有云端 id 的本机作业退回行内 `done` 字段。
- 完成/取消完成都可撤销，不需要 `confirmed`。

### 4. 可见性与权限
- 作业板是全班共享：云端 `homework` 表 `archived=false` 的行所有已认证同学可见。
- 用户自己「隐藏」的作业（`store.hwHide`）不会出现在 AI 列表里，属于个人视图，不影响别人。
- **删除权限：发布者本人或管理员**。其他人（非发布者、非管理员）调用 `deleteHomework` 会被拒绝；此时应告知用户只能在自己的作业板隐藏，不要重复尝试删除。
- 发布者字段只用于权限判断，**不要向用户展示学号（sid）、手机号等隐私字段**。

### 5. 附件
- 附件以 JSON 存在 `attachments` 列，元素含名称/类型/大小/base64 内容。
- **AI 侧只输出附件名称、大小、MIME 类型（`attachments[].name/size/sizeText/type`），绝不输出 base64、data URI 或文件内容**；需要打开附件时引导用户到作业板操作。

## 二、接口依赖与编排

| 接口 | 作用 | 前置条件 | 上下游 |
|---|---|---|---|
| `getHomeworkSummary` | 作业概览：待交/已完成/已过截止条数 + 最近到期一条 | 已身份验证 | 用户泛问「还有多少作业」时先用；再按需 `listHomework` |
| `listHomework` | 作业列表（状态/科目/关键词/条数） | 已身份验证 | 返回 `items[].id` 供详情/完成/删除引用 |
| `getHomeworkDetail` | 单条作业详情（完整内容 + 附件元信息） | 已身份验证 + 有效 `homeworkId` | `homeworkId` 只能取 `listHomework` 的 `items[].id` |
| `setHomeworkDone` | 标记完成/取消完成 | 已身份验证 + 有效 `homeworkId` | 用户说「做完了/交了」为 `done=true`；「还没做」为 `false` |
| `publishHomework` | 发布作业给全班 | 已身份验证 + 用户确认 + `confirmed=true` | 发布前先向用户复述科目/内容/截止时间 |
| `deleteHomework` | 删除作业（全班不可见） | 已身份验证 + 本人或管理员 + 用户确认 + `confirmed=true` | 先 `listHomework`/`getHomeworkDetail` 确认是哪一条 |

典型流程：
1. 用户问「还有多少作业没做」→ `getHomeworkSummary` → 展示概览并追问是否看待交列表。
2. 用户问「这周有什么作业」→ `listHomework`（`status=pending`）→ 需要时 `getHomeworkDetail`。
3. 用户说「数学作业我做完了」→ 先 `listHomework`（`subject=数学`）找到唯一一条 → `setHomeworkDone`（`done=true`）；多条同名时先问用户是哪一条，不要随便勾选。
4. 用户说「帮我发个作业」→ 先问清科目、内容、截止时间 → 复述确认 → `publishHomework`（`confirmed=true`）。
5. 用户说「把那条作业删了」→ `listHomework` 定位 → 说明只有发布者/管理员可删 → 确认后 `deleteHomework`（`confirmed=true`）。

### ID 规则（硬约束）
- 所有 `homeworkId` 必须取自接口返回的真实 `id` 原值，**禁止从用户自然语言推断、禁止编造、禁止使用示例值**。
- 上下文没有有效 id 时，先调用 `listHomework` 获取；接口返回 `invalid-input`（未找到）时按其提示重新获取，**不要用同一 id 重复重试**。
- 本机未上云的作业 id 以 `local_` 开头（接口内部生成），同样只能从接口返回中获得。

## 三、写操作与确认规则
- **`publishHomework` 与 `deleteHomework` 属于写操作/破坏性操作**：入参必须有 `confirmed:true`。
  - 首次调用应不传 `confirmed`（或传 `false`）→ 接口返回「尚未执行」的 `need-confirm` 结果 → 向用户复述将要执行的内容并等待确认 → 用户明确同意后再次调用并传 `confirmed=true`。
  - **绝不静默执行**，也绝不把「用户没说不行」当作确认。
- `setHomeworkDone` 可撤销，无需 `confirmed`；调用成功后再向用户陈述结果。
- 动作类接口未返回成功前，不要向用户宣称「已发布 / 已删除 / 已标记完成」。

## 四、失败兜底
- **网络不可用**：作业列表优先使用本机缓存（`store.homework`），仍可查看与标记完成；文案会注明「来自本机缓存」。完全无缓存时返回网络错误，引导稍后重试或打开作业板。
- **标记完成失败**：本机已生效并进入待补发队列，接口返回 `pending=true`；告知用户「已在本机生效，联网后自动同步」，不要重复调用。
- **发布失败**：作业已保存在本机（`pending=true`），联网后主包自动补发；告知用户其他同学暂时看不到，**请勿重复发布**。
- **删除失败**：云端未确认时本机数据保留，返回网络/云端错误；告知用户稍后重试，不要重复调用。
- **未认证**：所有接口返回 `identity-required` 并引导打开身份验证页（学号+姓名）；不要在本机猜测身份或展示班级数据。
- **空结果**：不是错误。说明「没有查到」，并给出替代动作（换关键词、看全部、去作业板）。

## 五、返回与展示约定
- 成功结果 `content` 写「本次事实 + 下一步动作」，例如「共查到 3 条待交作业。请展示作业卡片，并询问用户是否需要查看某条详情或标记完成。」
- `structuredContent` 含 `pagePath`（作业板页面路径，正文可渲染蓝链）与结构化数据；`_meta.cardData` 只给原子组件渲染，模型不读。
- 卡片 `homework-card` 关联作业板 `/pages/hw/hw`；接力 query 约定：`hw?tab=pending|done|all&id=<id>`。
- 本 SKILL 不涉及抽签、通知、课表等其它业务；跨业务需求交给对应 SKILL。

## 六、失败/边界示例
- 用户问「我上学期的高数作业」→ 大概率已被三天规则清除：说明作业板只保留未清除的作业，并引导到作业板查看。
- 用户说「作业都做完了」→ 先用 `listHomework(status=pending)` 确认条数，再逐条询问是否全部标记，**不要一次性批量勾选未确认的作业**。
- 用户要发布但没说内容 → 询问内容，不要编造；内容为空时接口返回 `invalid-input`。
