# 班级身份与工作台（classIdentity）

本技能负责「我是谁、班里有什么、今天该做什么」：班级身份验证、本班名单与班委、工作台总览、工具目录、使用说明。
班级工具站的所有其他技能（作业、通知、课表、抽签、体测、点名、我的账户）都以通过本技能完成身份验证为前提。

## 一、身份前提（全局规则）

1. 本机没有班级身份时，班级数据接口无法返回真实数据。调用任何班级数据接口前不需要先探测：直接调用即可，接口会在未认证时返回 `identity-required` 失败结果。
2. 收到 `identity-required` 时，照实告诉用户「班级数据需要先完成身份验证（学号 + 姓名）」，并说明进入身份页验证后回到对话重试即可；不要反复重试同一个接口，也不要让用户把学号发在对话里替你验证。
3. 只有 `verifyClassIdentity` 可以在没有身份时调用；它成功后，本机保存身份并同步班级名单，再引导用户使用其他技能。
4. 页面与卡片不展示学号、手机号、宿舍号；名单里只出现座号、姓名、角色/徽章。即使 structuredContent 里带了这些字段（如没有），也不要在回复里复述学号。

## 二、接口清单与依赖

| 接口 | 作用 | 何时调用 | 依赖/前置 |
|---|---|---|---|
| `verifyClassIdentity` | 用学号+姓名验证班级身份，成功后保存本机身份并同步名单 | 用户明确说出自己的学号和姓名并要求验证/登录/进入班级工具时 | 无（唯一免身份接口） |
| `getMyProfile` | 我的身份卡：是否已验证、姓名、角色、徽章、是否管理员、班级人数 | 问「我是谁/我的身份/是不是班委/我验证了吗」 | 需要身份；名单人数来自本机名单缓存 |
| `listClassMembers` | 班级名单（可按关键字/仅班委筛选、分页），不含学号 | 问「班里有哪些人/某某在不在/名单第几页」 | 需要身份；本机名单为空时接口会自动同步一次 |
| `getCommittee` | 班委名单（有职务的成员，管理员优先、按座号排序） | 问「班委有谁/谁负责什么」 | 需要身份；同 `listClassMembers` 的名单缓存 |
| `getMyOverview` | 我的数据概览：待交作业、已完成作业、抽签结果条数、体测记录条数 | 问「我还有什么没做/我的记录」 | 需要身份；读本机缓存，不联网 |
| `getToolsDirectory` | 工具目录：首页快捷（前 4 个）与全部工具（含分类和简介） | 问「有哪些功能/工具/怎么调整顺序」 | 不强制身份；非管理员不返回「统计」工具 |
| `getUsageGuide` | 使用说明：身份、功能、同步、隐私、工具章节 | 问「怎么用/有什么功能/数据怎么同步」 | 不强制身份；纯静态文案 |
| `getWorkspaceOverview` | 工作台总览：周次、今日课程、下一节课、作业待交、通知待处理、首页快捷 | 问「今天有什么课/今天要做什么/工作台」 | 需要身份；课程取本机课表缓存，未缓存时 `todayCourses` 为空并在 content 说明 |

## 三、意图分流

- 「验证身份 / 我是谁 / 登录 / 进入班级」→ `verifyClassIdentity`（只有用户给出 10 位学号 + 姓名时调用；缺任一项先追问，不要编造）。
- 「我的身份 / 我的角色 / 我是班委吗 / 我验证成功了吗」→ `getMyProfile`。
- 「班里有哪些人 / 名单 / 某某在不在 / 只看看班委」→ `getCommittee`（仅班委）或 `listClassMembers`（全名单；用户说了关键字就传 `keyword`，说了第几页就传 `page`）。
- 「班委是谁 / 各科课代表 / 谁管什么」→ `getCommittee`（`role` 字段是职务）。
- 「我今天要做什么 / 今天几节课 / 下节课是什么 / 工作台」→ `getWorkspaceOverview`。
- 「我还有什么作业没交 / 我的抽签记录 / 我的体测记录」→ `getMyOverview`（只给数量与极简摘要；要明细转作业/抽签/体测技能）。
- 「有哪些工具 / 怎么排序 / 功能目录」→ `getToolsDirectory`。
- 「怎么用 / 使用说明 / 数据同步和隐私怎么设置」→ `getUsageGuide`，`section` 取 `identity|features|sync|privacy|tools|all`；用户没指定就传 `all`。
- 用户意图明显超出本技能（作业、通知、课表明细、抽签、体测、点名、反馈、统计）→ 不要用本技能接口凑答案，转到对应技能；跨技能编排优先「工作台总览 → 具体技能」。

## 四、典型编排

1. 新用户第一次来：「我想查作业」→ 先 `getMyProfile`（或直接调用作业接口）；若返回 `identity-required`，说明需要先验证，用户提供学号+姓名后调用 `verifyClassIdentity`，成功后再次调用用户原本要用的接口。
2. 身份验证成功 → 用 `getWorkspaceOverview` 给一句工作台现状（今天课程 / 待交作业 / 待处理通知），再问要不要深入某一项。
3. 名单查询：`roleOnly=true` 等价于 `getCommittee`；用户提到具体姓名先用 `keyword` 过滤，`total=0` 时说明没有匹配成员，不要编造名字。
4. 用户说「我是 xx，学号 xxxxxxxxxx」但只是想聊天/查询时，不要自动验证并保存身份；只有用户明确要求验证或表示要进入班级工具时才调用 `verifyClassIdentity`。

## 五、跨接口约束

1. 身份只来自 `verifyClassIdentity` 的云端校验结果；不要根据用户自称的姓名/角色推断身份，也不要把用户自报信息写进身份。
2. 所有姓名、座号、角色必须取自接口返回；不要编造姓名、座号、职务、班级人数。
3. 需要分页时，先看返回的 `total/page/pageSize`，再决定是否翻页；单页最多 50 条。
4. 卡片由系统渲染，正文只写「事实 + 下一步动作」；不要把 structuredContent 整段复述成表格或 JSON。
5. 验证失败（学号不匹配、网络失败）时把接口返回的原因转述给用户，并给出下一步（核对学号姓名 / 检查网络后重试），不要连续用同一组信息重试。

## 六、失败兜底

- `identity-required`：见「身份前提」，引导完成验证；部分接口返回 handoff 可在用户点卡片时进入身份页。
- `invalid-input`：按接口说明补齐（学号 10 位数字、姓名非空、section 取值等），必要时追问用户。
- 网络失败：说明当前无法连云端；本机已有缓存的功能（我的概览、工具目录、使用说明）仍可回答。
- 空结果：如实说「没有查到」，并给替代动作（换关键字、看全部名单、先验证身份同步名单），不要用 `isError` 伪装成失败。
- 名单缓存为空：`listClassMembers`/`getCommittee` 会自动尝试同步一次；仍为空时提示用户检查网络，并可在页面查看。

## 七、与其他 SKILL 的协作

- 作业/通知/课表/抽签/体测/点名/账户技能共享同一班级身份；本技能完成后无需重复验证。
- 「工作台」只是入口：需要作业明细、通知详情、课表明细、抽签结果时，调用对应技能，不要把本技能的总览当作完整数据。
- 账户技能负责同步状态与数据管理（`getSyncStatus`、`syncNow`、`getDataOverview` 等），本技能不重复提供。
