# 我的账户与数据（myAccount）

本技能负责「账号、同步、我的数据」：云同步状态与开关、立即同步、本机/云端数据概览与导出、清除数据、反馈建议、管理员访问统计。
所有接口都依赖班级身份（`getSyncStatus` 除外，它可以在未验证时如实返回 verified=false 并引导验证）。

## 一、身份前提

1. 除 `getSyncStatus` 外，本技能接口在未认证时返回 `identity-required` 失败结果；此时照实说明「班级数据需要先完成身份验证（学号+姓名）」，引导用户去身份页，不要反复重试。
2. 页面与回复不出现学号、手机号、设备号、token；`getVisitStats` 只按姓名聚合，不显示学号/设备号。
3. 反馈、访问统计是云端记录：清除云端数据时不会删除它们，必须如实说明。

## 二、接口清单与依赖

| 接口 | 作用 | 何时调用 | 前置/依赖 |
|---|---|---|---|
| `getSyncStatus` | 同步状态：是否验证、云同步是否关闭、是否在清除后的抑制期、待补发条数、上次同步时间、云端是否可用 | 问「同步了吗/为什么没同步/我的数据到云端了吗」 | 无需身份（会显示 verified=false） |
| `syncNow` | 立即刷新四类小表：marks、homework、fitrecs、userdata；通知整表太重，不在此接口拉 | 用户明确说「立即同步/刷新数据」 | 需要身份与云同步开启 |
| `setCloudSync` | 打开/关闭云同步（关闭 = 仅本机，不再拉取/推送；重新打开时补发待补发） | 用户说「关闭云同步/只在本地/打开同步」 | 需要身份 |
| `getDataOverview` | 本机存储占用与各类数据条数、云端同步范围清单、不可删除项 | 问「占多少空间/存了什么/同步哪些数据」 | 需要身份 |
| `exportMyData` | 导出我的数据（JSON 文本，≤8KB，不含 token/学号/名单原文） | 用户要「导出/备份我的数据」 | 需要身份 |
| `clearCloudData` | 清除云端「我的数据」（userdata 覆盖为空、marks 置否、体测归档；不可撤销） | 用户明确要求清除云端数据并已确认 | 需要身份 + `confirmed=true` |
| `clearLocalData` | 清除本机数据（保留身份，云端副本不动） | 用户明确要求清空本机缓存并已确认 | 需要身份 + `confirmed=true` |
| `submitFeedback` | 提交反馈建议 | 用户提出意见/问题/bug 并希望提交 | 需要身份；反馈原文由平台透传 |
| `listMyFeedback` | 我的反馈记录（内容摘要、是否已处理、时间） | 问「我提的反馈处理了吗/我的反馈记录」 | 需要身份 |
| `markFeedbackDone` | 标记反馈为已处理（仅管理员） | 管理员要求「把反馈标为已处理」 | 需要身份 + 管理员 |
| `getVisitStats` | 访问统计（按姓名/按天/按小时聚合，仅管理员，不显示学号） | 管理员问「最近访问情况/统计」 | 需要身份 + 管理员 |

## 三、意图分流

- 「同步状态 / 为什么没同步 / 云端有我的数据吗 / 上次什么时候同步」→ `getSyncStatus`。
- 「立即同步 / 刷新一下数据」→ `syncNow`（先看 `getSyncStatus`：若已关闭云同步，先提示打开，不要硬同步）。
- 「关掉云同步 / 只用本机 / 重新打开同步」→ `setCloudSync`（`enabled=false` 关闭；`enabled=true` 打开）。
- 「占多少空间 / 存了哪些数据 / 同步哪些内容 / 能删哪些」→ `getDataOverview`。
- 「导出 / 备份我的数据」→ `exportMyData`，把 `jsonText` 作为导出结果交给用户（说明未包含身份凭证与名单原文）。
- 「清除云端我的数据」→ 先说明影响（userdata 清空、勾选置否、体测归档；访问统计与反馈删不掉；本机保留），确认后 `clearCloudData{confirmed:true}`。
- 「清空本机数据 / 清除缓存」→ 先说明影响（保留身份、云端不动），确认后 `clearLocalData{confirmed:true}`。
- 「我要反馈 / 提个建议 / 报 bug」→ `submitFeedback`；不要再向用户索取或编造 QQ / 微信等联系方式。
- 「我的反馈 / 反馈处理了吗」→ `listMyFeedback`。
- 「把这条反馈标记为已处理」（管理员）→ `markFeedbackDone`。
- 「最近有多少人用 / 访问统计 / 谁最活跃」（管理员）→ `getVisitStats`；非管理员调用会得到权限失败，如实说明仅管理员可看，不要伪造数据。

## 四、破坏性操作确认规则

1. `clearCloudData`、`clearLocalData` 属于破坏性操作：`confirmed !== true` 时接口返回 `need-confirm`，不会执行。必须先向用户说明「将要清什么、什么清不掉、能否恢复」，用户明确同意后再调用并传 `confirmed=true`。
2. 清除云端后进入抑制期：不自动把云端副本写回；用户下次修改同步内容时才会重新上传。要如实说明，不要说「已全部删除」。
3. `setCloudSync`、`syncNow`、提交反馈、标记反馈不是破坏性操作，不需要 `confirmed`。
4. 任何写操作都要以接口返回为准：接口成功前不要向用户声称「已完成」。

## 五、数据与隐私口径

1. 导出内容只含用户自己改动/同步范围的数据 + 身份摘要（姓名/角色），不含 token、学号、完整班级名单、派生名单文本、设备 id。
2. `getDataOverview` 只报条数与体积，不输出任何名单/通知原文。
3. 访问统计只按姓名聚合，回复里不要出现学号或设备标识；数据为空时如实说没有记录。
4. 同步范围固定为：作业完成、通知已处理、通知置顶、工具栏顺序、体测录入、抽签参数、分组与名单、点名名单与到·假、隐藏项、课表偏好、通知提醒偏好、昵称。新增类别前先不要承诺。

## 六、失败兜底

- `identity-required`：引导完成身份验证后重试；`getSyncStatus` 除外（它本身可以未验证调用）。
- `need-confirm`：说明操作内容并向用户确认，用户同意后再传 `confirmed=true`。
- 网络失败：说明云端暂时不可用；本机数据不受影响，可稍后重试；已关闭云同步时先提示打开。
- 云端不可用或未配置：`getSyncStatus` 中 `network.enabled=false`，如实说明「当前只能使用本机数据」。
- 权限不足（非管理员看统计/标记反馈）：说明只有管理员可以操作，不要尝试绕过。
- 空结果（没有反馈、没有访问记录）：如实说「没有查到」，给出可做的替代动作，不要返回 isError。

## 七、与其他 SKILL 的协作

- 反馈与统计依赖身份；未验证时先走 identity 技能。
- 「我的数据概览」中的作业/抽签/体测明细属于作业、抽签、体测技能；本技能只负责账户、同步、导出与清除。
- 同步失败不影响本机功能；可以继续使用作业/通知/课表等本机缓存功能。
